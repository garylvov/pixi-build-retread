# driver_exit_baseline.txt -- HARNESS-EXIT-3. The RATCHET for FAMILY B.
#
# FAMILY B discovers every `.sbatch` in the task tree and drives it through the
# payload seam. Discovery over a tree this size finds wrappers that predate the
# lane, wrappers whose swallow is DELIBERATE because they ARE the fixture for
# the defect, and wrappers the seam cannot drive. A guard that goes red on all
# of them is a guard nobody keeps green, and a permanently red guard is the same
# defect as no guard. So this file names them, and the guard is red only on a
# wrapper that is NOT here.
#
# THE RULES, enforced by driver_exit_guard.sh and not by good intentions:
#   * A NEW SWALLOWER IS FIXED, NOT BASELINED. The guard pins the row counts
#     below in BASELINE_MAX_SWALLOW / BASELINE_MAX_UNCOVERED and REFUSES (rc 4)
#     if this file is larger than the pin.
#   * The pins come DOWN with the file, never up.
#   * Every row carries the reason it is here. "it was already broken" is not
#     one. "it is the fixture that must swallow" and "its payload is invoked by
#     a path the seam cannot reach" are.
#   * A row whose wrapper now re-raises is printed as STALE. Delete it and
#     lower the pin in the same commit.
#
# SWALLOW rows: the wrapper ran through the seam and exited 0 on a payload
# stubbed FAILING at 7.
